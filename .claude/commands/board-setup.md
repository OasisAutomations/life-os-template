The user is setting up (or changing) their Board of Advisors.

**Mode:** $ARGUMENTS (empty = full setup; "redo" = full setup, overwrite; "add" = skip to adding one advisor)

## Steps
1. Read `01-identity/board-onboarding.md` (the questionnaire + catalog), `01-identity/profile.md`,
   and `01-identity/board-of-advisors.md`. Also read `north-star/` — anything already
   answered there doesn't need to be asked again.
2. **If the board is already set up** and the mode is empty, show the current roster and ask
   whether they want to redo it, add a seat, or swap someone. Then stop and wait.
3. **Questionnaire (Part A).** Ask the questions two or three at a time, conversationally,
   waiting for answers between rounds. Accept short answers and "skip." Don't lecture.
4. Write `01-identity/profile.md` from the answers, including the **Shared briefing**
   (3–6 non-negotiables drawn from bottleneck, derailers, and constraints). Show it and
   ask if anything's off.
5. **Recommend a board (Part B).** One advisor per chosen seat, with a one-line "why you"
   for each, their blind spot, and at least one counterweight to the user's derailer.
   Invite swaps. Wait for the user to confirm the roster.
6. Write `01-identity/board-of-advisors.md` in the exact section shape the file shows,
   specific to this user's profile (not generic bios). Fill the seat-coverage table.
7. Offer a test run with `/ask-the-board`.

## Rules
- The user picks. Recommend, explain, then defer to their choice.
- Advisors are simulations of public ideas — never claim they're real or endorse anything.
- Keep it to 2–5 seats. If they want more, suggest which to cut.
